### Blocked-attempt counts, nudges, and event notifications — implementation plan

Verified against branch master at 0.6.0 (HEAD `cf5e428`). Line numbers are hints; symbols are authoritative.

## 0. Shape of the solution (both features share one spine)

```
listener.rs handle()  --refused host-->  Observe hook (leaf std::Mutex, no await)
                                             |
                                     Daemon.attempts: attempts::Buffer (dedup 10 s, cap 256)
                                             |  drained once per scheduler tick (1 s), under the state lock
                                             v
                     st.stats.credit_attempt()  +  ActiveBlock.attempts += 1  +  Daemon.events.push(Attempt)
procwatch sweep()  --new kills-->  Daemon.app_kills_pending (unchanged)  +  Daemon.events.push(AppKill)
                                             |
                                 GetStatus: recent_events (bounded 32, seq-numbered) + active[].attempts
                                             |
GUI Rust status watcher (5 s poll) --> notify::Watch::poll(prev, cur, settings) -> Vec<Notice> -> notify()
```

Every new daemon-side container is a **leaf `std::sync::Mutex` held for microseconds and never across an await**, which is exactly the discipline `Daemon.forwardable` and `Daemon.health` already use (`crates/daemon/src/main.rs:60-66, 82-89`). The scheduler tick is the single consumer, mirroring the `app_kills_pending` drain (`crates/daemon/src/scheduler.rs:76-85`). The `applied` → `state` lock order (`crates/daemon/src/enforce.rs:111-114`) is untouched: the proxy hook never takes a tokio lock, and the scheduler takes the leaf locks while already holding `state`, which the health precedent permits.

### A1. Where a refused connection becomes an "attempt"

`crates/daemon/src/listener.rs`

- Add a hook type beside `Decide` (line 233):
  ```rust
  /// Called with the parsed hostname of every connection that was REFUSED
  /// (decide said no). Accept-path rules as for `Decide`: never blocks, never
  ```

- Thread it: `ProxyListener::start(decide, observe)` (266), `serve(listeners, decide, observe)` (280), `spawn_accept(listener, probe, permits, decide, observe)` (432), `handle(stream, probe, &decide, &observe)` (491).
- Call site: in `handle`, after `if decide(&host) { forward…; return; }` (499-503) and before the `:80` write (505-510), add `observe(&host);`. One call per refused connection on both probes; a forwarded (on-break) connection or one with no parseable hostname reports nothing. The existing `debug!(%host, …)` at 504 stays the only line that logs a hostname.
- Tests (`no_forward()` at 1534 gains a sibling `recording()` that pushes into an `Arc<Mutex<Vec<String>>>`; `ephemeral_with_budget` at 1519 takes the observe hook):
  - `a_refused_http_connection_is_observed_once` / `…_tls_…` — one call, lowercased host.
  - `a_connection_with_no_hostname_is_not_observed`.
  - `a_forwarded_connection_is_not_observed` — decide returns `true` for a host that cannot resolve (`"nonexistent.invalid"`), `forward` closes silently, observe is never called.

### A2. Transport and attribution (`crates/daemon/src/enforce.rs`, new `crates/daemon/src/attempts.rs`, `main.rs`)

- **Only hosts the daemon is enforcing count.** A developer's own `127.0.0.1 myapp.test` hosts line also lands on our `:80` while a block is active (and is refused today); it must not become an "attempt". So `enforce::sync` refreshes a second leaf set next to `forwardable` (139-146): `*daemon.enforced.lock() = domains.iter().cloned().collect()` (the union from `union_domains`, 426-446). New `Daemon.enforced: Arc<std::sync::Mutex<HashSet<String>>>`, documented like `forwardable` (main.rs:60-66).
- Pure fold, next to `forwardable_set`:
  ```rust
  /// The blocklist entry a refused hostname belongs to, or None if it is not
  /// ours. `www.x` folds to `x` because `hosts::render_block` writes both
  /// (hosts.rs:191-194); nothing else is folded — subdomains are not blocked.
  fn canonical_attempt(host: &str, enforced: &HashSet<String>) -> Option<String>
  ```
- The hook is built in `ensure_detection` beside the `decide` closure (392-399): capture `daemon.enforced.clone()` and an `Arc<std::sync::Mutex<attempts::Buffer>>`; body: `if let Some(c) = canonical_attempt(host, &enforced.lock()…) { buffer.lock()….record(c, now_unix()); }`.
- `attempts.rs` (new, pure, no IO):
  ```rust
  pub const WINDOW_SECS: u64 = 10;   // one attempt per host per window — a page load counts once
  pub const PENDING_CAP: usize = 256;
  pub struct Buffer { last: HashMap<String, u64>, pending: Vec<(String, u64)>, dropped: u64 }
  impl Buffer {
      pub fn record(&mut self, host: String, now: u64) -> bool;   // false = suppressed by window or cap
      pub fn drain(&mut self, now: u64) -> Drained { attempts: Vec<(String,u64)>, dropped: u64 } // prunes `last` older than WINDOW
  }
  ```
  `last` is bounded by the enforced-host set (only canonical hosts are recorded); `pending` by the cap. Tests: `same_host_within_window_counts_once`, `window_elapsed_counts_again`, `distinct_hosts_count_separately`, `pending_cap_drops_and_counts`, `drain_prunes_stale_last_seen`, `clock_step_backwards_does_not_underflow` (saturating).
- Why a leaf mutex and not an mpsc channel: a channel still needs a consumer task, the dedup has to live somewhere before the state lock, and the scheduler tick is already the consumer for procwatch's counter. Same reason `app_kills_pending` is an atomic rather than a channel.

### A7. Nudge

Fires from the Rust status watcher (see B4) off `recent_events` of kind `attempt`:
- Title `"{host} blocked"`, body `"{N}{st|nd|rd|th} attempt this hour · {block name}"`. N = attempts for that host seen in the last 3600 s (GUI-side ring of seen attempt events, pruned).

- Toggle: **`Settings.attempt_nudges: bool`, default `false`, daemon-side** (`lib.rs:939-970`; hand-written `Default` gains `attempt_nudges: false`; `set_settings_wire_tag_round_trips` at 1849 and the ipc literal at 1946 updated; `old_settings_without_attempt_nudges_defaults_off` test mirrors 1829). ### B2. `recent_events` (`crates/core/src/lib.rs`, new `crates/daemon/src/events.rs`)

```rust
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum EventKind { Attempt, AppKill, #[default] #[serde(other)] Unknown }   // Health-style forward compat (lib.rs:972-979)

#[derive(Clone, Debug, Default, PartialEq, Eq, Serialize, Deserialize)]
#[serde(default)]
pub struct RecentEvent {
    /// Monotonic per daemon run, starts at 1; the client's dedup key.
    pub seq: u64,
    pub unix: u64,
    pub kind: EventKind,
    pub block_id: u64,
    /// `attempt`: the blocklist entry (canonical hostname). `app_kill`: the
    /// matched app entry's label. Never more than MAX_EVENT_DETAIL_CHARS.

```
Daemon: `Daemon.events: std::sync::Mutex<events::Log>`; `Log { next_seq, ring: VecDeque<RecentEvent> }`, `RECENT_EVENTS_CAP = 32`, `push(kind, block_id, detail, now) -> u64` (truncates detail, drops control chars), `snapshot() -> Vec<RecentEvent>` oldest-first. Add the field to the two `Daemon` constructors (`main.rs:288-299`, `ipc.rs:1421-1436`).

Why `seq` and not timestamps: two kills in one second are two events. Restart handling is a GUI rule (B4), so no boot id is needed.

### B4. GUI watcher refactor (`crates/gui/src/main.rs`, new `crates/gui/src/notify.rs`)

Keep the decision in **Rust**, where it already lives. `spawn_status_watcher` (877-999) exists precisely so notifications do not depend on a visible webview — the window hides to tray and the task runs for the life of the process (doc at 877-884). Moving the comparison to TS would either double-fire (unless the Rust block start/end path is deleted) or tie notifications to a hidden webview's timers. The function the user asked for is still pure and unit-tested, just in Rust:

```rust
pub struct Snapshot { pub now: u64, pub active: Vec<ActiveBlock>, pub pomodoro: Option<PomodoroStatus>, pub health: Health, pub events: Vec<RecentEvent> }
pub struct Notice { pub title: String, pub body: String }
#[derive(Default)]
pub struct Watch {
    prev: Option<Snapshot>, prev_red: Option<bool>, last_seq: Option<u64>,
    warned_breaks: HashSet<(u64, u64)>, suppress_ended: HashSet<u64>,
    nudged: HashMap<String, u64>, app_notified: HashMap<(u64, String), u64>,
    attempts_seen: VecDeque<(u64, String)>,
}
impl Watch {
    /// Everything to show for `cur` given the previous poll. Pure: the clock
    /// is `cur.now`. Always advances baselines; `settings` only decides what is returned.
    pub fn poll(&mut self, cur: Snapshot, settings: &Settings) -> Vec<Notice>;
}
```
Sequence rule inside `poll`: events with `seq > last_seq` are new; if the newest `seq` is *lower* than `last_seq` the daemon restarted — set `last_seq` to it and emit nothing (no replay); first poll sets `last_seq` without emitting; events older than 120 s are ignored (GUI resumed from sleep). `enforcement_red` moves into the module unchanged with its test (1176-1212). The watcher loop (940-997) shrinks to: build `Snapshot` → `for n in watch.poll(snap, &settings) { notify(&app, &n.title, &n.body) }`, keeping the tray-tooltip lines.

Tests in `notify.rs` (one `Snapshot` builder, no clock): `first_poll_is_silent_and_sets_baselines`, `block_start_and_end_unchanged`, `pomodoro_phase_changes_notify_once_each`, `pomodoro_completion_replaces_block_ended`, `pomodoro_stop_replaces_block_ended`, `break_warning_fires_once_on_the_60s_edge_and_never_for_short_breaks`, `break_over_skips_pomodoro_blocks`, `app_kill_events_dedup_by_seq_and_rate_limit`, `attempt_nudge_needs_both_toggles_counts_per_hour_and_rate_limits`, `daemon_restart_resets_seq_without_replay`, `stale_events_after_sleep_are_ignored`, `notifications_off_advances_every_baseline`, `red_edge_unchanged`.

If the owner prefers the TS home for vitest after all: `crates/gui/ui/src/notify.ts` with the identical `poll` contract, `@tauri-apps/plugin-notification` from the webview, and deletion of `main.rs:975-996` — a strictly worse trade, recorded in the plan doc as the rejected alternative.

### B5. Settings

### C2. Clock guard — recommendation: BOOTTIME-anchored trusted clock

**Why not the alternatives.** A pure `Instant` virtual clock uses `CLOCK_MONOTONIC`, which stops during suspend — a laptop asleep 2 h would run every block 2 h long. A wall-delta-only heuristic cannot tell sleep from `date -s`. `CLOCK_BOOTTIME` counts suspend, so comparing the per-tick wall delta against the BOOTTIME delta separates the two exactly: equal → honest (including sleep); different → a step. Note the unit already has `ProtectClock=yes` and `Restart=always` (`packaging/grepfocusd.service`), and `date -s` needs root, so this is friction against sudo-in-the-moment, consistent with README *Known limits*.

**Behaviour (precise):**
- `trusted` is the daemon's time base for every block-timing decision. Per tick, with `wall_delta` and `boot_delta` since the last tick:
  - `|wall_delta − boot_delta| ≤ 2 s` → `trusted += wall_delta` (tracks wall; leap seconds and slew absorbed).
  - otherwise → `trusted += boot_delta`, `warn!` once per step ("clock step of ±N s detected; block timing continues on elapsed time").
  - then, if **idle** (`active.is_empty() && pomodoro.is_none()`) → `trusted = wall` (resync in both directions). While anything runs, `trusted` never resyncs — so a forward step during a block only makes the block end later in real time, never earlier; a backward step changes nothing. (Resyncing downward while idle is required: otherwise a forward-then-back step pair while idle would leave `trusted` ahead of wall and expire the next *scheduled* block — whose `ends_at` is a wall instant — immediately.)
- Suspend: both deltas include the sleep → `trusted` tracks wall → a block ends at its wall-clock end, or on the first tick after resume if that has passed.
- Restart continuity: persist `ClockAnchor { trusted_unix, boot_secs, boot_id }` in `State` (updated in memory every tick, rides any save, like `high_water_unix` `lib.rs:1177-1181`). At startup, if `/proc/sys/kernel/random/boot_id` matches → `trusted = anchor.trusted + (boot_now − anchor.boot_secs)` (exact, however stale the save); else `trusted = max(wall, high_water_unix)`. This closes "step the clock, kill −9, let systemd restart". A reboot with a changed clock remains root-plus-physical — document it.
- License expiry keeps `effective_now`/`high_water_unix` (`main.rs:104-106`) untouched.

### D3. GUI — recommendation: `<input type="file">` for import, Rust-side write for export, no dialog plugin

- Import: a hidden `<input type="file" accept=".json,application/json">` → WebKitGTK shows its native GTK file chooser (wry does not override `run-file-chooser`), `file.text()` works on the `http://localhost` origin. Zero dependencies.
- Export: a Tauri command that writes the file and returns the path. `<a download>` of a Blob would also work, but WebKitGTK's default download handler saves silently into XDG Downloads, fails silently on an existing name, and wry only surfaces download events if the window registers `on_download` — and there is still no Save-As without the plugin. A Rust write costs the same zero dependencies and tells the user exactly where the file went. `tauri-plugin-dialog` stays the option if a real Save-As is wanted later (new crate, `dialog:allow-save/open` under the remote ACL).

`crates/gui/src/main.rs`: `#[tauri::command] async fn export_config() -> Result<String, String>` (daemon `ExportConfig` → `serde_json::to_string_pretty` → write with `create_new(true)` to `export_dir()/grepfocus-config-YYYYMMDD-HHMMSS.json`, return the path) and `#[tauri::command] async fn import_config(json: String, mode: ImportMode) -> Result<ImportSummary, String>` (`config_doc::parse` first, like `add_block` pre-validates at `:46-48`).
